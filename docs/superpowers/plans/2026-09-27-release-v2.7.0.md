# v2.7.0 Release Plan

**目标：** 基于 v2.6.1 以来的新功能与修复，发布新的 v2.7.0 tag；不移动既有 tag。先将领先远端的 72cdba3 推送到 main，再发布。

**架构：** `skills/VERSION` 为脚本输入的版本源，根 VERSION、package.json、各平台插件和 marketplace 由同一脚本同步。发布说明是仓库内可追溯文档，不修改被忽略的外部 CHANGELOG.md 符号链接。tag 必须指向通过测试的 release commit，远端 main 与 tag 都核验一致。

**实施：**
1. 检查远端 tag/分支、历史和破坏性变更，确认版本决策；先修脚本漏同步模块插件的缺陷及测试。
2. 用脚本同步 v2.7.0；写版本说明，包含 features/fixes/evaluation caveat；检查全部 manifest。
3. 运行 npm test、自检、git diff 检查；发布前确认版本及推送意图。
4. commit → 新建 v2.7.0 tag → push main → push tag → 校验远端 commit 与 tag；失败时如实报告本地状态，不覆盖或删除旧 tag。

**验收与清理：** 不创建临时 worktree/branch；测试临时目录在 finally 中删除；工作区干净，远端可见新 tag。纯 CLI 发布没有视觉 UI，截图不适用，以远端 refs 和测试输出为准。
