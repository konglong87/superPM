## 跨 Agent 交互规则

当流程要求与用户交互时：

1. 如果当前环境支持 AskUserQuestion，使用 AskUserQuestion（最佳体验）。
2. 如果当前环境不支持 AskUserQuestion，必须用普通聊天消息提出同样问题。
3. 一次只问一个问题。
4. 提问后必须停止当前回合，等待用户回答（STOP and WAIT）。

## 适用场景

- 用户说"监控竞品""竞品情报""竞品怎么变""竞品月报""竞品异动预警"
- 与 `pm-market` / `pm-search` 区分：那些是**一次性研究**；本技能是**周期性监控 + 异动预警**，强调基线与对比。

---

## 执行流程

### 步骤 1: 确定监控对象与维度（主 agent - 用户交互）

使用 AskUserQuestion 询问：

> 🎯 竞品监控设置
>
> 你想监控哪些竞品？监控哪些维度？
>
> A) 自动沿用市场调研报告中的竞品清单
> B) 我手动指定竞品（请提供名称）
> C) 仅监控头部 1-3 个核心竞品
>
> 监控维度（可多选）：版本/功能更新、定价变动、市场/融资动作、用户舆情、招聘/组织信号

记录到变量 `COMPETITORS` 与 `WATCH_DIMS`。

---

### 步骤 2: 建立/读取监控基线（主 agent）

如果 `docs/01-需求调研/竞品监控月报.md` 不存在 → 进入**首次基线模式**：

使用 Agent 工具并行派发 subagent，对每个竞品做全量快照（搜索优先）：

```
Tool: Agent
Parameters:
  subagent_type: "general-purpose"
  description: "竞品基线调研-{竞品名}"
  prompt: |
    你是竞品情报分析师。请对竞品「{竞品名}」建立当前快照。

    **搜索优先级**：首选 AnySearch（定位脚本后 python3 调用），失败降级 Exa MCP，最后 WebSearch（标注「⚠️ 降级模式」）。
    **监控维度**：{WATCH_DIMS}
    **要求**：提取最新版本/功能、定价、近期动态、舆情基调（正面/中性/负面）、关键信号。
    **输出 JSON**：
    ```json
    {
      "competitor": "{竞品名}",
      "snapshot": {"version": "...", "pricing": "...", "news": "...", "sentiment": "正面/中性/负面", "signals": ["..."]},
      "sources": [{"title": "...", "url": "..."}]
    }
    ```
```

如果已存在上期月报 → 读取并提取上期基线值，供本期对比。

---

### 步骤 3: 设定监控节奏与预警阈值（主 agent - 用户交互）

使用 AskUserQuestion 确认：

> 📅 监控节奏
>
> A) 月度监控（推荐）
> B) 双周监控
> C) 季度监控
>
> 异动预警阈值（示例）：
> - 定价变动 ≥ {X}%
> - 大版本/核心功能上线
> - 负面舆情集中爆发
> - 融资/组织重大变动

记录到变量 `CADENCE` 与 `ALERT_RULES`。

---

### 步骤 4: 派发 subagent 做本期情报收集（核心优化）

与步骤 2 同样派发 subagent（并行），但 prompt 增加「与上期对比，标记变化」：

```
对比上期基线：{上期快照}
重点识别本期相对上期的异动（新增/变更/消失），并判断影响（高/中/低）。
```

主 agent 收集所有竞品结果。

---

### 步骤 5: 生成竞品监控月报 + 异动预警（主 agent）

使用 Write 工具生成 `docs/01-需求调研/竞品监控月报.md`：

```markdown
# {产品名称} 竞品监控月报（{周期}）

## 文档信息
- 周期: {起} ~ {止}
- 监控竞品: {列表}
- 生成工具: super-pm / pm-competitor

---

## 一、本期异动预警（重点）
| 竞品 | 异动 | 类型 | 影响 | 我方建议 |
|------|------|------|------|---------|
| {竞品} | {异动} | 版本/定价/舆情/融资 | 高/中/低 | {建议} |

## 二、竞品快照对比
| 维度 | 上期 | 本期 | 变化 |
|------|------|------|------|
| {竞品A·版本} | ... | ... | ... |
| {竞品A·定价} | ... | ... | ... |
| {竞品B·舆情} | ... | ... | ... |

## 三、行业信号
- {融资/并购/新政等}

## 四、我方机会与威胁
- 机会: {从竞品弱点中找}
- 威胁: {从竞品动作中找}

## 五、下一步建议
1. /pm-position - 基于竞品动态重新校准定位
2. /pm-priority - 将竞品威胁纳入需求优先级
3. /pm-market - 需要深度专项研究时
```

---

### 步骤 6: 推荐下一步（主 agent）

> ✅ 竞品监控月报已生成：`docs/01-需求调研/竞品监控月报.md`
>
> 建议执行：
> 1. /pm-position - 校准产品定位
> 2. /pm-priority - 竞品威胁转需求
> 3. /pm-market - 深度专项研究

## 搜索依赖说明

- **AnySearch**（首选）→ **Exa MCP**（备选）→ **WebSearch**（兜底，标注「⚠️ 降级模式」）。
- 舆情类监控优先垂类域（科技媒体、应用商店评论、社交平台）。

---

## 输出质量对比

**✅ Good 示例**：
- 有基线对比：「竞品A 上月定价 ¥99，本月涨至 ¥129（+30%），触发预警」
- 有影响判断与建议：「影响：高；建议：评估我方是否跟涨或主打性价比」
- 有来源：「来源：竞品官网公告 2026-07-20」

**❌ Bad 示例**：
- 罗列新闻无对比：「竞品A 发布了新功能」
- 无影响判断
- 无来源

---

## 常见误区 / Red Flags — STOP

| 误区 | 正确做法 |
|------|---------|
| 把监控做成一次性研究 | 监控必须有基线 + 周期对比 |
| 堆砌新闻无预警 | 必须标记异动与影响级别 |
| 无来源 | 每条异动附来源 |
| 忽略我方行动建议 | 监控终点是对我方策略的建议 |
