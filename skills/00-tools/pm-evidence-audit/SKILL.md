# PM 证据审计

本 skill 审的是**结论与证据之间的支持关系**，不是替用户改写业务判断。`pm-prd-review` 负责文档结构、可行性、验收标准；本 skill 检查“市场规模、用户痛点、竞品功能、增长效果”等主张是否真的被来源支持。正式判定请按同目录的 [`references/rubric.md`](references/rubric.md)；该文件随单技能安装，不依赖完整技能包。

## 输入与边界

- 接受用户给出的报告、片段、可访问的文档路径或资料链接。没有材料时，只问一条最关键的问题：要审哪份材料或哪些结论？
- 默认**只读并在聊天中报告**：不默认写入、修改或覆盖源文件。用户明确要保存时再确认输出路径和覆盖风险。
- 用户说**不联网**时，只用已提供材料；禁止联网、不要把外部来源写成“已核实”。资料不可访问、需要登录或无权限时如实标注，不能编造来源、数据、访谈或截图。
- 不向第三方上传用户的内部材料。必要的检索仅针对公开、非敏感主张；若环境没有搜索工具，停止外部核验并说明局限。

## 审计流程

1. **界定范围**：列出会影响产品决策的关键主张，按在原文中的位置编号 `CLAIM-001`、`CLAIM-002`……；长文先审高影响结论，不假装全文已覆盖。把原话、指标口径、时间/地区/人群记清楚。
2. **追踪证据**：逐条找主张引用的原始资料，核对作者/机构、发布日期或数据采集日期、原始值与定义。来源存在**不等于**它支持当前主张；转述文章、摘要和推断需回溯到可访问的原始材料。用户允许联网且工具可用时才进一步核验；不得凭搜索摘要宣称看过全文。
3. **处理矛盾与推断**：有可信来源冲突时并列双方和口径差异，不能挑一个支持自己结论的来源；因果、外推和预测要拆出前提。按 rubric 的固定状态常量判定，给出“为何如此”及无法确认的地方。
4. **汇报下一步**：对高影响且证据薄弱的主张给出最小的下一步验证动作和责任人建议。审计不能自动把 `UNVERIFIED` 改成 `VERIFIED`，也不自动修改用户原文。

## 输出格式

先写审计范围、检查时间、是否联网和未覆盖部分。随后输出可追溯表：

| 主张 ID / 原文位置 | 主张摘要 | 状态 | 来源与日期 | 依据和局限 | 决策影响 | 下一步验证动作 |
|---|---|---|---|---|---|---|
| CLAIM-001 / §2 | … | UNVERIFIED | 未提供；不可假设 | 无法找到支持该口径的数据 | 高 | 请提供原始报告或调整措辞 |

`状态`只使用 rubric 定义的枚举常量；不能用模糊的“基本可信”代替。来源附可访问链接或文件位置及日期；不存在的来源写“未提供”，不可伪造。最后列出**可以保留、需降级措辞、需补证据、存在冲突**四类建议。高风险结论要说明如果验证失败，哪项产品决策需要重审。

如果用户要求对源报告直接修订，先另行确认修改范围并保留原文；本次证据审计的默认产物仍是独立报告。
